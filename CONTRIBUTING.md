# Contributing

Thanks for considering a contribution.

## Workflow
1. Fork the repo and create a branch off `main`: `feature/short-description` or `fix/short-description`
2. Make your changes with clear, atomic commits
3. Open a PR against `main` using the PR template
4. Link any related issue

## Commit messages
Use conventional prefixes where it makes sense:
`feat:`, `fix:`, `refactor:`, `docs:`, `chore:`, `ci:`

## Code style
- Match existing naming conventions in the file/package you're editing
- Keep functions/classes focused — prefer splitting large files over adding to them
